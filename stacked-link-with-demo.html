Start the local model server (PowerShell)

No API key is required. Open two PowerShell windows. In the first, run the model command below and wait until the server is ready. Keep both windows open while using the app.

llama serve `
  -m "D:\AI\models\Qwen3.8-27B-UD-Q4_K_M.gguf" `
  --mmproj "D:\AI\models\mmproj-BF16.gguf" `
  --device Vulkan1 `
  --n-gpu-layers auto `
  --ctx-size 8192 `
  --parallel 1 `
  --cache-ram 0 `
  --batch-size 512 `
  --ubatch-size 128 `
  --reasoning off `
  --host 127.0.0.1 `
  --port 9931 `
  --alias qwen3.8-27b `
  --no-webui

Memory settings: --parallel 1 runs one request at a time. --cache-ram 0 disables the extra RAM prompt cache; model weights and active context buffers remain loaded between cards. --batch-size 512 --ubatch-size 128 uses smaller processing chunks to reduce peak working memory, potentially at some cost to speed. The model, image resolution and 8192-token context are unchanged.

In the second PowerShell window, start card2vcf:

cd D:\Dev\monica\card2vcf
npm.cmd start

The model listens only on this PC at port 9931. The app opens at http://127.0.0.1:8765. Stop either server with Ctrl+C in its window. Model and projector paths must match your installed files.

Changing only llama flags? Finish or cancel extraction, restart llama, then click Check model when it is ready. Keep card2vcf and this tab open; no npm restart or webpage refresh is needed.

Performance on this PC: the 27B model file is about 15.3 GiB, while Vulkan1 is an RTX 5060 Laptop GPU with about 8 GiB VRAM. Automatic offloading therefore leaves substantial CPU work. One server slot matches this app?s sequential queue; it does not eliminate the model?s memory bottleneck. For substantially faster batches, use a smaller generative vision model with its matching projector that fits GPU memory. The installed 2B embedding model is not a replacement for a chat/extraction model.

Reasoning is already disabled by --reasoning off. The ?preserving reasoning? message concerns chat history; changing that setting alone is not an established speed fix. Image token limits can reduce processing time but may lose tiny text, so they are not reduced by default.

Optional: if you later enable --api-key on the model server, set the same value in $env:CARD2VCF_API_KEY before starting card2vcf. Otherwise leave both unset.
